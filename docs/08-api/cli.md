# API & CLI

## Purpose
The API layer is the gateway through which external agents and humans interact with Matis-mem.

## Interfaces

### 1. CLI (The Human Interface)
The primary way for developers to manage the daemon, browse memory, and configure adapters.
- `matis status`: Check daemon and adapter health.
- `matis browse`: Launch the TUI.
- `matis query "..."`: Search semantic memory from the shell.
- `matis adr new`: Create a new Architecture Decision Record.

### 2. MCP (Model Context Protocol)
The primary way for AI agents (Claude, IDEs) to consume memory.
- **Tools**: `get_context`, `search_memory`, `list_decisions`.
- **Resources**: `timeline`, `knowledge_graph`.
- **Prompts**: Pre-defined context injection templates.

### 3. REST / WebSocket API
A local server for IDE plugins and dashboards.
- `GET /events`: Stream live engineering events.
- `POST /knowledge`: Manually promote a snippet to semantic memory.
- `GET /context`: Retrieve a context bundle for a specific file or task.

## Security
- **Localhost Only**: The API binds only to `127.0.0.1` by default.
- **Auth Tokens**: Clients must provide a bearer token generated by the CLI.
- **Scoped Access**: Read-only access by default for AI agents unless explicitly granted "Capture" permissions.
